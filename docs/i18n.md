# Internationalization (i18n) Guide

Battle Base provides lightweight, zero-dependency localization supporting three locales:

- `ja` — 日本語 (Default fallback)
- `en` — English
- `zh-CN` — 简体中文

---

## 1. Directory Structure & Localization Layers

Battle Base separates **UI text templates** from **Football Entity display localizations**:

```text
data/
  manual/
    entity-localizations.json   # Source-of-truth manual localizations & aliases for 418 Players, 28 Clubs, 7 Leagues
  entities/
    players.json                # Build artifact (populated by scripts/build-entity-index.mjs)
    clubs.json                  # Build artifact (populated by scripts/build-entity-index.mjs)
    leagues.json                # Build artifact (populated by scripts/build-entity-index.mjs)
  reports/
    football-localization-report.json
    football-localization-report.md
public/
  data/
    team-seasons.js             # Canonical English gameplay dataset (NEVER localized in place)
    entity-localizations.js     # Generated browser runtime display index (built by scripts/build-localization-index.mjs)
  i18n/
    i18n.js                     # Core runtime (t(), formatEntityName(), formatPlayerName(), formatClubName(), formatLeagueName(), getPlayerDisplayName(), getClubDisplayName())
    ja.js                       # Japanese UI dictionary
    en.js                       # English UI dictionary
    zh-CN.js                    # Simplified Chinese UI dictionary
  game/
    shared/
      event-formatters.js       # Pure formatters converting structured Draft History & Match Events to localized strings
scripts/
  build-entity-index.mjs            # Builds data/entities/*.json including localizedNames & aliases
  build-localization-index.mjs      # Builds public/data/entity-localizations.js & localization audit report
  validate-football-localization.mjs # Validates 100% entity localization coverage, aliases, fixtures, and runtime behavior
  check-entity-localization-leaks.mjs # Audits UI render files for raw canonical name leaks
  check-i18n.mjs                    # Static verifier for UI key parity and {placeholder} consistency
```

---

## 2. Locale Resolution Priority

When the app boots, `i18n.js` resolves the active locale in the following order:

1. **User Manual Selection** — Saved in `localStorage` under `battle-base-locale` when the user changes `#lang-select`.
2. **`localStorage` (`battle-base-locale`)** — Persisted preference across page reloads.
3. **`navigator.language` / `navigator.languages`** — Normalized via prefix matching:
   - `ja`, `ja-JP` -> `ja`
   - `zh`, `zh-CN`, `zh-Hans`, `zh-SG` -> `zh-CN`
   - `en`, `en-US`, `en-GB` -> `en`
4. **Fallback** — Defaults to `ja`.

## 3. Core API (`public/i18n/i18n.js`)

### UI Strings (`public/i18n/*.js`)
- `getLocale()`: Returns current locale code (`'ja' | 'en' | 'zh-CN'`).
- `setLocale(locale)`: Normalizes locale, persists to `localStorage`, updates `document.documentElement.lang`, and notifies subscribers.
- `t(key, params?, localeOverride?)`: Resolves dot-notation key from `public/i18n/{ja,en,zh-CN}.js`.
- `subscribeLocaleChange(callback)`: Registers a listener invoked whenever the locale changes; returns an `unsubscribe` function.

### Football Entity Names (`data/manual/entity-localizations.json` → `entity build` → `public/data/entity-localizations.js`)
- `formatEntityName(type, canonicalName, localeOverride?)`: Formats a canonical `'player' | 'club' | 'league'` name into the active locale's primary display name. Falls back to canonical English if unknown; never throws.
- `formatPlayerName(canonicalPlayer, localeOverride?)`: Returns primary localized player name.
- `formatClubName(canonicalClub, localeOverride?)`: Returns primary localized club name.
- `formatLeagueName(canonicalLeague, localeOverride?)`: Returns primary localized league name.
- `getPlayerDisplayName(canonicalPlayer, localeOverride?)` / `getClubDisplayName(canonicalClub, localeOverride?)`:
  - Returns `{ primary, secondary }`:
    - `en`: `{ primary: canonicalEnglish, secondary: null }` (never duplicates English twice)
    - `zh-CN`: `{ primary: localizedChinese, secondary: canonicalEnglish }`
    - `ja`: `{ primary: localizedJapanese, secondary: canonicalEnglish }`
  - Used on large UI surfaces (such as Draft candidate cards) to show the localized primary name alongside the secondary canonical English name, while compact surfaces (Draft History, Match Events, Roster slots, Reveal rows) use `formatPlayerName()` / `formatClubName()` for primary-only display.

## 4. Canonical Data & Render Boundary Policy

To guarantee that deterministic simulation, bot decisions, and multiplayer synchronization are 100% independent of UI language:

1. **Canonical Data (`public/data/team-seasons.js`) is English Only**:
   - `player.name`, `player.club`, and `player.league` inside `public/data/team-seasons.js`, draft state, match simulation (`public/game/match/engine.js`), RNG, and network payloads remain strictly in canonical English (`Zinedine Zidane`, `Real Madrid`, `La Liga`).
2. **Localization Happens Exclusively at the UI Render Boundary**:
   - Draft Roll metadata, Reroll hints, Draft candidate cards, Ready roster, Team slot lists, Roster Reveal, Draft History (`formatHistoryEvent`), and Match Events (`formatMatchEvent` for `player`, `defender`, `goalkeeper`, `scorer`, `assist`) convert canonical English names to localized display strings at render time.
3. **Slot & Role Codes**:
   - Slot IDs (`GK1`, `DF1..DF4`, `MF1..MF3`, `FW1..FW3`) and Role codes (`GK`, `DF`, `MF`, `FW`) remain canonical uppercase codes.
   - Mechanics branding (`ROLL`, `LOCK IN`, `DRAFT COMPLETE`, `ROSTER REVEAL`, `MATCH`, `GOAL`, `FULL TIME`, `READY`, `HIDDEN`) is preserved intentionally across locales.

---

## 5. Building & Validating Localizations

Never hand-edit `data/entities/*.json` or `public/data/entity-localizations.js` directly. Always edit `data/manual/entity-localizations.json` (for football entities) or `public/i18n/*.js` (for UI strings), then run:

```bash
node scripts/build-entity-index.mjs
node scripts/build-localization-index.mjs
node scripts/validate-football-localization.mjs
node scripts/check-entity-localization-leaks.mjs
node scripts/check-i18n.mjs
```
