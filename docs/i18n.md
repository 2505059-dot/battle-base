# Internationalization (i18n) Guide

Battle Base provides lightweight, zero-dependency localization supporting three locales:

- `ja` — 日本語 (Default fallback)
- `en` — English
- `zh-CN` — 简体中文

---

## 1. Directory Structure

```text
public/
  i18n/
    i18n.js      # Core runtime (locale detection, storage, t(), subscribeLocaleChange(), formatLeagueName())
    ja.js        # Japanese dictionary
    en.js        # English dictionary
    zh-CN.js     # Simplified Chinese dictionary
  game/
    shared/
      event-formatters.js  # Pure formatters converting structured Draft History & Match Events to localized strings
scripts/
  check-i18n.mjs # Static verifier for key parity and {placeholder} consistency across all locales
```

---

## 2. Locale Resolution Priority

When the app boots, `i18n.js` resolves the active locale in the following order:

1. **User Manual Selection** — Saved in `localStorage` under `battle-base-locale` when the user changes `#lang-select`.
2. **`localStorage` (`battle-base-locale`)** — Persisted preference across page reloads.
3. **`navigator.language` / `navigator.languages`** — Normalized via prefix matching:
   - `ja`, `ja-JP` -> `ja`
   - `zh`, `zh-CN`, `zh-Hans`, `zh-SG` -> `zh-CN`
   - `en`, `en-US`, `en-GB` -> `en`
4. **Fallback** — Defaults to `ja`.

---

## 3. Core API (`public/i18n/i18n.js`)

- `getLocale()`: Returns current locale code (`'ja' | 'en' | 'zh-CN'`).
- `setLocale(locale, options?)`: Normalizes locale, persists to `localStorage` (unless `{ persist: false }`), updates `document.documentElement.lang`, and notifies subscribers.
- `t(key, params?)`: Resolves dot-notation key (e.g. `t('match.events.goal', { player: 'Lionel Messi' })`). Falls back to `ja` dictionary if a key is missing in the current locale, and finally returns `key` if not found anywhere.
- `subscribeLocaleChange(callback)`: Registers a listener invoked whenever the locale changes; returns an `unsubscribe` function.
- `formatLeagueName(leagueId)`: Translates canonical league names (`Premier League`, `La Liga`, `Serie A`, `Bundesliga`, `Ligue 1`, `Eredivisie`, `Primeira Liga`) into the current display language while keeping canonical dataset values untouched.

---

## 4. Decoupling Game Logic & Network State from Display Text

To guarantee that deterministic simulation and multiplayer synchronization are completely independent of UI language:

1. **Network Payloads (`ctx.send`)**:
   - Only canonical IDs, numbers, and action codes are transmitted (`roll`, `reroll`, `pick`, `match_start`).
   - Two players in the same room can use different languages simultaneously.
2. **Draft History (`state.history`)**:
   - Stores structured event objects (`{ type: 'draft.roll' | 'draft.reroll' | 'draft.pick', ... }`).
   - Rendered on demand via `formatHistoryEvent(entry)` in `public/game/shared/event-formatters.js`.
3. **Match Simulation (`generateMatchScript` in `public/game/match/engine.js`)**:
   - Emits pure structured event objects (`type`, `minute`, `team`, `player`, `gk`, `variant`, etc.) without natural-language strings.
   - Template variations (`variant`) consume the exact same seeded RNG sequence regardless of active locale.
   - Rendered on demand via `formatMatchEvent(event, teamNames)` and `formatMatchEventBadge(event)`.
4. **Data & Domain Policy**:
   - **Player names** and **Club names** remain in their canonical English dataset form.
   - **Slot IDs** (`GK`, `DF`, `MF`, `FW`, `FLEX`) remain canonical uppercase codes.
   - **League names** are localized at render time via `formatLeagueName(league)`.

---

## 5. Adding or Updating Translations

1. Add the new key to `public/i18n/ja.js`, `public/i18n/en.js`, and `public/i18n/zh-CN.js`.
2. Ensure any `{placeholder}` variables match across all three files.
3. Run the verification script:

```bash
node scripts/check-i18n.mjs
```
