# Historical FIFA card search

The checked-in full-batch findings and limitations are summarized in [the final research report](results/report.md).

This isolated research pipeline maps 99 PlayerSeason rows from 11 early squads to 95 distinct canonical players and searches public football-card databases. It does not modify rosters, PlayerSeason IDs, the ability-v2 data, or the match engine.

## Run

Requires Node.js 20+ and no package installation. From the repository root:

```powershell
node research/historical-card-search/scripts/prepare-input.mjs
node research/historical-card-search/scripts/search.mjs
node research/historical-card-search/scripts/search.mjs --site=wefut --editions=14
node research/historical-card-search/scripts/verify-samples.mjs
node research/historical-card-search/scripts/verify-regressions.mjs
node research/historical-card-search/scripts/search.mjs --all
# After WeFUT acquisition ends, collect each edition's public HTML header before merging.
node research/historical-card-search/scripts/collect-wefut-headers.mjs
# If running isolated per-source workers, merge only each source's 95 matching input jobs.
node research/historical-card-search/scripts/merge-workers.mjs
# Share repeated WeFUT header schema evidence while retaining each raw card row.
node research/historical-card-search/scripts/compact-candidates.mjs
node research/historical-card-search/scripts/build-report.mjs
# Reclassify a saved merged candidate/checkpoint file without network requests.
node research/historical-card-search/scripts/reclassify-identities.mjs --progress=research/historical-card-search/.cache/merged-progress.json
# Reparse an older Nexon checkpoint from saved HTTP responses only.
node research/historical-card-search/scripts/reparse-nexon-cache.mjs --progress=research/historical-card-search/.cache/full-progress.json --http-cache=research/historical-card-search/.cache/http
```

The default run checks eight representative players. `--site=wefut`, `--site=fo4`, `--site=fo3`, or `--site=nexon-fco` selects one adapter. `--editions=14,26,27` limits a WeFUT run; the full run covers FIFA14–FC27. Stable `searchEntityKey` values join inputs, candidates, checkpoints, and reports; unresolved `playerId` values remain null. `--all` resumes player/site checkpoints from `.cache/full-progress.json`; transient network/5xx results receive one retry per process and remain retryable on a later resume. HTTP 401/403/429 responses halt further requests to the same origin and are retained as blocked checkpoints. Exact HTTP responses are cached under `.cache/http`; both are gitignored. `HISTORICAL_CARD_RATE_MS` sets the per-process delay between uncached requests (default 900 ms). The WeFUT header collector uses public edition-page GETs, reuses successful cached pages, and writes `results/wefut-edition-headers.json`; pass `--editions=14,15,...` to limit the edition set.

Coverage records successful HTTP responses, verified name filtering, candidate observation, identity confidence, and `search_completeness`/`possibly_truncated` separately per site and PlayerSeason row. An HTTP 200 with unrelated rows is not a matched search; uncertain single-page searches remain partial. `card_found` means a non-mismatching candidate was observed at the row's confidence level; `confirmed_linked_identity` is true only for high-confidence identity evidence. `blocked_or_unavailable` is reserved for transport errors and explicit 401/403/429 responses; transient 5xx responses remain failure reasons and pending retries. A full run writes `results/candidates.json` and `results/coverage-report.json`; sample runs write one `results/sample-<site>-candidates.json`. Candidate records retain all observed variants and raw source fields. The report maps findings back to all 99 PlayerSeason rows and never chooses a card by highest OVR or converts ratings between games.

For WeFUT, `attributes_found` means at least 20 usable detailed numeric ability fields were observed; it does not mean the field set is complete. Editions 14–17 and 19 require unique `Nation`/`Nationality`, `Min`, and `Max` header delimiters. Editions 20–21 expose 75 labeled columns but lack the legacy `Min`/`Max` boundary, so their attributes remain unknown. Edition 18 page retrieval returned HTTP 500 and its header is unavailable. Editions 22–27 use a separately verified modern layout: the public page must declare its matching server-side `/ajax/getPlayers/{edition}` source, label `Rating`/`Rtg`, `Position(s)`/`Pos`, and `Nation` at the checked metadata columns, and each candidate row must contain exactly 75 contiguous numeric fields matching the public header. The reusable adapter derives DataTables `iColumns`, `sColumns`, and `mDataProp` length from that edition's observed header; it records an unknown request shape and sends no search POST if the table width is unavailable. The saved batch used a 74-column POST; the cached modern responses still contain all 75 numeric cells matching the visible headers. Modern completeness requires the fixed 35-field detailed set, including labeled `Composure`; a missing expected field cannot shrink the expected set. Only nonblank labeled fields are mapped; `Potential` stays development metadata and blank work-rate cells are never guessed. Duplicate detailed labels are excluded from active values but retained in raw columns. Summary ratings and skill/work-rate metadata are stored separately. If a version header or row alignment is unavailable, no active normalized attributes are emitted; raw row cells remain available and completeness stays unknown. The collector records each edition's header hash, mapping strategy, status, and source URL for reproducibility.

After merging a full batch, `scripts/compact-candidates.mjs` replaces repeated per-candidate WeFUT header schemas with `rawFields.wefutHeaderEvidenceRef`, pointing to the shared `results/wefut-edition-headers.json` entry by edition and SHA-256. The compactor verifies the referenced header hash and before/after candidate-data and ID projections. It retains original numeric row cells, card markup, IDs, URLs, normalized attributes, and each candidate's completeness state; only the duplicated header schema and repeated present-column listing are shared.

`merge-workers.mjs` is the offline finalizer for isolated source runs. It reads the completed per-site checkpoints without changing them or making requests, filters candidates/jobs/errors by both source and the 95 stable input keys, preserves pending-retry states and every returned card variant, refreshes source-local IDs and identity confidence, then writes the merged checkpoint, candidates, and `results/run-manifest.json`. It requires an attempted job for every input key on all four sources. Output files are restricted to `results/` for candidates/manifests and the default `.cache/full-progress.json` or `.cache/merged/` for the merged checkpoint. Before writing, it resolves existing paths and rejects aliases or temporary files that overlap one another, scripts, inputs, worker roots, raw HTTP caches, or any other directory. The manifest records input/checkpoint hashes, acquisition-worker code hashes separately from offline enrichment/report code hashes, the Node runtime, source counts, and Nexon static-index cache metadata. It records the 900 ms request-delay default but leaves the actual worker delay unknown because `HISTORICAL_CARD_RATE_MS` is an environment override not saved in checkpoints. Worker timestamp strings are preserved as stored; pass `--task-clock-utc=YYYY-MM-DDTHH:mm:ssZ` to record an app-clock anchor when hosts report different offsets. Then run `build-report.mjs` to generate the 99-row coverage report.

Card identifiers in `cardId` are source-local and paired with `sourceIdNamespace`; equal numeric values from different sites are not treated as a match. `sourcePlayerId` is populated only when a source explicitly provides a verified base-person ID. WeFUT row cell 66 has a blank source header and is retained only in raw fields; it is not treated as a person ID. FO3/FO4 route IDs and Nexon's season-specific SPID remain in `sourceCardId` and do not stand in for person IDs. `numericIdentityEvidence` remains null unless an independent cross-source link is established. A high-confidence identity requires an explicit same-namespace contract or a documented crosswalk to an input `existingExternalIds` namespace. No crosswalk has been verified between current site IDs and the checked-in SoFIFA/FIFAIndex IDs, so those numeric coincidences do not promote confidence. The offline reclassifier preserves the prior confidence reason, keeps source-local IDs, and recomputes trusted card/OVR/attribute flags without network access.

## Public sources and request behavior

- **WeFUT**: the public database route `/player-database/{edition}` configures a server-side DataTables request to `/ajax/getPlayers/{edition}`. The reusable adapter derives its request column count from the matching public table, sends the global `sSearch`, observed filter fields, and page-issued CSRF cookie, and skips the search request if the table width is unknown. The saved batch used 74 columns; cached modern responses provide 75 numeric fields matching the modern table header. Some saved responses still contain unrelated high-OVR rows with `iTotalDisplayRecords=101`; the reason the server does not apply the supplied name term is unverified. The adapter stops on unrelated first-page rows, repeated pages, or its offset safety cap, and marks filter uncertainty/truncation rather than treating those rows as a match or a global absence. FIFA14–FC26 are included; FC27 was also observed populated. Rows provide OVR, positions, card version, identity fields, and detailed attributes. No profile detail fetch is needed for the same card fields.
- **FIFA Addict FO4**: search uses `/fo4db?playername=...`, followed by public SSR card profiles. Search-page pagination is unverified, so one-page observations are marked partial/possibly truncated in the denominator. Profile DOB, nationality, card season, OVR, and six summary attributes are extracted. Server-rendered detailed stats are zero placeholders and excluded. The hydrated detail API returned HTTP 401 to ordinary retrieval; no client token was synthesized or replayed. Playwright and playwright-core were not installed in the environment, so browser-DOM attribute retrieval is not implemented or claimed tested. Opaque profile route IDs remain source-local; no reliable same-card cross-source link was established in the inspected records, which is not proof that such an ID is absent elsewhere.
- **FIFA Addict FO3**: `/fo3db.php?q=player&name=...&limit=500` searches without season filters. The 500-row UI limit is preserved; search completeness is unknown/partial even below the cap because exhaustive pagination was not established. Public profiles contain card positions, OVR, season, DOB, nationality, and other identity context; sampled detailed-stat nodes were blank. The page-linked attribute POST was tested with the profile page cookie jar and page-issued token: it returned HTTP 200 with JSON content type but a non-JSON body, so attribute availability remains unverified (not classified as an access block).
- **Nexon FC Online** (`nexon-fco`, optional fallback): reads the public `spid.json` and `seasonid.json` static indexes, submits the public PlayerList form (page 1 only), and reads PlayerAbility fragments using the ordinary page defaults `n1Strong=1`, `n1Grow=0`, and zero team modifiers. A same-normalized-Korean-name SPID group can be fully enumerated for returned seed names from the static index, separately from the unknown/partial PlayerList search completeness; a shared Korean display name is not proof of identity. Each saved ability fragment has 40 ordered `li.ab` entries: 6 card-summary ratings and 34 detailed attributes, identified from their DOM sections. All raw entries are retained; same-section conflicting duplicates are occurrence-qualified and make the normalized detail result ambiguous. `scripts/reparse-nexon-cache.mjs` can reparse an older progress file from saved HTTP cache only; a missing cache is reported and never triggers a request. The selected ability state is preserved with `base_state_verified=false`; no stat subtraction or cross-game conversion is done. This source is reported separately and cannot silently resolve FO4 identity gaps.

The report's Nexon conclusion counts 34-field detailed-attribute candidates separately from six summary ratings and records the page-selected `n1Strong=1` state with `baseStateVerified=false`. Its “possible FO4 gap candidates” are input-row/entity overlaps only; `verifiedSameCardAttributeFills` remains zero unless an independent same-card link is established.

The adapters do not sign in, bypass a challenge, spoof an API key, replay a browser-only token, or evade access restrictions. HTTP, parser, request-filter, and pagination failures are recorded. A successful empty search means only “no result observed,” not global absence.

## Input audit and interpretation

The input files are derived from checked-in roster, alias, and ability-v2 audit sources. The audit currently lists 92 unavailable rows, 89 name/ambiguity findings, and 41 position findings among these 99 rows. Those categories overlap and do not define a 42-row unresolved cohort. In particular, searches do not establish the historic club-season association. Low confidence means name-only evidence; high confidence requires a same-namespace ID or an evidenced crosswalk; `unverified` is retained for Nexon results without a crosswalk. Name mismatches remain in candidate files for audit but do not count as linked card coverage.
